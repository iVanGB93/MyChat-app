Negotiated media lane (prepared APK76, October 9 evening)
- Bottleneck addressed: persistent axon v1 serialized every attachment request with control traffic and imposed 50ms start spacing. Existing 4-request read-ahead only queued locally.
- Updated peers negotiate mediaLane=1 in hello only when the adapter supports it. Authenticated media-request/media-response IDs use a separate pending map on the existing axon socket/data channel. This is a logical lane, not a second physical connection or a new encryption protocol.
- Window starts at 1, increases to 4 as replies arrive, halves on replies slower than 1 second, and limits starts to one per 5ms. At most 4 outgoing calls and 4 inbound handlers per connection; queues remain bounded. Control requests no longer wait behind an in-flight media request. Close/timeout/lock drains pending requests; native background ticks enforce deadlines.
- Adapter queues allow at most 120,000 queued bytes after media admission. Native authentication admission remains 64 frames/minute, old attachment budget 3856; new LAN media budget 28256 includes control headroom. Updated RTC native guard permits 28256 after authentication, while JS enforces negotiation and tighter control/media budgets.
- Old peers/native binaries use the old serialized/paced path. No frame exceeds the existing 20,000-byte transport ceiling. Both upload and download workers process bounded windows of up to 4 chunks and checkpoint verified contiguous progress. Custody writes remain transactional and serialized.
- Preserved contract: 4096-byte encrypted chunks, ciphertext representation, Merkle proofs, signatures, keys/nonces/AAD, manifest/receipt formats and stored jobs are unchanged. No new security proof is claimed. This implementation pipelines small chunks; larger binary blocks remain a possible later optimization, and it does not promise to saturate broadband.
