Production changes
1. Atomic stream staging replaces the delete-prefix-then-move sequence. Only a
   hash-verified attempt can reach staging; the transfer worker still verifies
   the resulting file before publishing/signing its receipt. An unsuccessful
   atomic rename does not delete the verified download prefix. No copy/delete
   fallback, message-format change, new cryptographic primitive, or bypass of
   peer/device/lease checks. This is process-failure-safe handoff, not a claim
   of power-loss/fsync durability.
   Android Files.move contract:
   https://developer.android.com/reference/java/nio/file/Files
2. Android API 24/25 do not expose the API 26 atomic-stage primitive. Capability
   negotiation and the receiver fall back to the existing verified chunk path.
   Guard and missing-native behavior covered by regression tests; no API 24/25
   physical device was tested in this run.
3. Native full-file checksum verification follows bounded, validated app-owned
   shared.json references for group media grants. It stays within the same
   account's shared payload directory. Malformed links, traversal and mismatched
   lengths fail closed. Previously the stream sender looked in the per-grant
   directory, causing unnecessary fallback for shared payloads. Group-path
   validation is covered by native tests; no new live group was created.
4. Shipping canonical leaf hash input restored to 8300 bytes. The temporary
   256 KiB chunk experiment allowance is gone; the shipping 4 KiB wire format
   and larger negotiated transport/write batches are unchanged.
5. Dev updater binds each ADB serial to its exact debugger target. Identical
   model names can no longer select the wrong phone for preservation checks.
