Direct-stream readiness and native preparation — October 14, 2026

Changes
The attachment stream adapter distinguishes unavailable-before-start from a
failed transfer. An unavailable result permits another attempt after one second;
encrypted chunk fallback keeps progressing meanwhile. A real stream failure
retains the existing 60-second suppression. Only true success advances the job
to complete-file verification. Exact authenticated recipient/device admission,
revocation, temporary-file isolation and signed receipts are unchanged.
This fixes a confirmed readiness suppression mechanism, not every possible
cause of route churn seen in the earlier audit. Chunk-source failure backoff
and actual disconnects can still add latency.

Preparation profiling measured 1399ms of encryption in a 2183ms 2 MiB run;
reads, writes and copy consumed only milliseconds. Android now uses its existing
Bouncy Castle 1.86 XChaCha20Poly1305 implementation on the attachment worker
pool. It reads the private staged content and writes ciphertext directly.
Each call handles at most 128 original 4096-byte chunks, returning only leaf
hashes. It does not change encryption chunk size, nonce derivation (first 24
bytes of SHA-256 of canonical AAD), AAD, ciphertext/tag layout, Merkle leaf
serialization, manifests, shared group payloads or receipt verification.

The JS module produces the same validated canonical AAD as its portable cipher.
Native paths accept validated owner/id rather than arbitrary paths, reject
symlinks/canonical-path changes, enforce exact input/output offsets and lengths,
bound AAD and batch sizes, and check interruption between chunks. Key/plaintext
byte buffers are cleared; immutable bridge strings/provider-internal copies are
subject to platform lifetime management, not claimed to be securely erased.
No keys, plaintext or private paths are logged. Local lock/cancellation is
checked before and after each native await; failures remove unpublished output
and retain the staged source for retry. Unsupported clients retain portable
preparation. Errors from a supported native API fail closed.

Validation
Full npm run check: 1109 passing tests, 3 skipped, 0 failed; typecheck,
dependency cycles, module boundaries and consolidation passed.
Two native known-answer tests cover independent Noble-generated v1 and shared
v2 ciphertext hashes and every leaf for a full chunk plus one-byte tail, split
across two calls (nonzero offset), and reject incorrect offsets/traversal.
JS regression tests cover prompt unavailable retry, bounded retry interval,
actual-failure fallback, cancellation, malformed/native-error results, lock
during native preparation, batching and byte-equivalent encrypted chunks.
These are implementation and interoperability checks, not a formal security
proof. Native module and both local debug clients compiled successfully.
