Measurement
Read the previous synthetic call's local journal without modifying it. Repeatedly
run canArchiveCallJournal (replays historical event/receipt validation); no archive
operation is performed. Same journal: phone 5 events/3 receipts, 11862 characters;
emulator 5 events/2 receipts, 10599 characters.
Before: phone warmed runs ~29.8 ms; emulator ~45–50 ms.
After: phone warmed runs ~11.9–12.2 ms; emulator ~5.3–8.6 ms.
First runs and warmups recorded separately in evidence. Sequential microbenchmark,
not a randomized end-to-end performance experiment.

Implementation
Existing signature verification already caches the pure signature result. Added
successful complete call-control/receipt verification reuse with exact keys:
event/receipt raw string, JSON of the complete pinned identity (and receipt's
referenced event), and the exact validation timestamp. Changed timestamps always
miss; changed record contents, signatures and event contents miss. Every cache
miss executes the previous verifier unchanged. Historical replay uses the original
admission time as before. Current-time admissions do not gain extended validity.
Mutable journal state, permissions, replay decisions, CAS and failures are not
cached. Returned objects are isolated by storing serialized successful values and
parsing on hits; consumers cannot poison cached results by mutating an object.
Two memory-only caches, each capped at 64 entries and 262144 combined key/value
UTF-16 code units (engine overhead additional). No disk or network storage.
