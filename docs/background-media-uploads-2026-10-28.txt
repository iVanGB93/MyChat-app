Background media uploads — 2026-10-28

Implementation:
- Android 14+ user-initiated JobScheduler task, scheduled from foreground queue admission or foreground recovery. Single native job per installation. No schedule polling.
- JobService starts the existing React Native headless entry. Its token grants native socket lifetime only while the Android job exists. The JS task takes/releases an independent shared-network lease.
- Durable preparation selections and outgoing job checkpoints stay authoritative. Completion requires confirmed message/attachment custody or recipient delivery, never a local preview or cursor reaching 100%.
- Task observes queue/ledger/account changes; native bounded waits observe OS cancellation. Reads are coalesced at 500ms. UI, calls and notification recovery retain independent leases.
- Android progress notification opens Axonic. Existing per-attachment pause/resume controls remain authoritative; resume can schedule a new job. Failed/paused work is preserved.
- Manual/automatic account locking stops upload work. Startup uses the existing remembered-session policy, never a credential bypass.
- JS lease budget 19 minutes, native deadline 20 minutes. Budget expiry preserves checkpoints and prompts reopen. User force-stop is not bypassed. Android system interruptions can reschedule the job; app foreground recovery also inspects unfinished work.
- Android below 14: no new background job; existing foreground/reopen recovery and explicit keep-open UI remain. This limitation is visible, not advertised as background support.
- Separate Dev phone update installed with data preserved; no official-app installation or release build. No queues/messages/identities deleted.

Validation:
- Native Kotlin compilation passed.
- Dev-only APK assembled locally for arm64-v8a and x86_64.
- TypeScript, module-boundary and service-cycle checks passed.
- 18 focused lifecycle/status/observation tests pass (14 task/lease/status plus 4 durable-observation checks).
- Android 16 emulator: isolated native job scheduled successfully, 11 of 12 timed progress steps ran after pressing Home; job completed and released its lifetime. This was a no-transfer probe, not throughput evidence.
- Restored the actual headless handler by reloading Dev. Empty-account native job refused work and showed the unlock-required notification.

Still required before release:

- Emulator probe does not prove end-to-end phone uploads or device-vendor battery behavior.
