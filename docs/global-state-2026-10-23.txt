GLOBAL STATE IMPLEMENTATION — 2026-10-23

Scope
Added Zustand 5.0.16 as a presentation/read-model layer over existing runtime
and durable storage. No production build, commit, push, deployment, data wipe,
or official-app installation. Existing unrelated work remains in place.

Implemented
- Shared account, foreground lifecycle, network/directory and live-peer views.
  One underlying subscription per observed source; equal snapshots do not notify.
  Connection expiry updates the shared live-peer view.
- Shared revision-aware chat loading and derived message presentation, with
  structural sharing and conversation indexes. Individual rooms subscribe to
  their own messages. Contacts-only consumers avoid loading their own chat copy.
- Account lock/switch clears private chat and transfer presentation; generation
  guards reject late reads. Failed reads preserve the last good view with error.
- Shared transfer progress: initial/foreground hydration, then committed job
  checkpoint events. Progress updates target attachment rows rather than causing
  parent chat screens to reread jobs and rebuild all progress lookups.
- Shared call signaling and separately leased media metadata. Native tracks,
  streams, encryption state and call controls remain owned by existing services.
  A previous call's cleanup cannot clear the next call's metadata.
- Shared notification preference presentation with coalesced reads and publish
  after successful durable writes; old reads cannot undo a completed write.
- Targeted avatar invalidation; an avatar change no longer clears every peer's
  cached avatar. Invalidated in-flight reads cannot reinstall stale entries.

Deliberate boundaries / follow-up
- Global state is not a second database or a new network protocol authority.
  Existing persistence, authorization, retry rules and runtime services remain
  authoritative. Cached presentation must not decide security permissions.
- Local compose text, gestures, scrolling, modal state and native media objects
  stay local. External-file existence is not permanently cached because users
  can delete shared media outside the app.
- Full ledger serialization and remaining per-list summary calculations were
  not replaced with an incremental database in this change.
- Physical-phone frame/scroll profiling and screen-sharing regression remain
  separate checks. Emulator correctness and projection savings do not establish
  a measured production FPS improvement.
- Existing production AAB predates these changes; no new AAB was built.
