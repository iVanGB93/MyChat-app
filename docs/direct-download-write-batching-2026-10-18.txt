Finding and implementation
The download worker verified/decrypted each 4 KiB chunk and the phone adapter
repeated directory/path/file checks, open, seek, write and close per chunk.
An optional writeChunks adapter now writes at most 32 contiguous verified
chunks at once. The worker retains at most 128 KiB of plaintext; the file
adapter temporarily copies at most another 128 KiB for one contiguous write.
These buffers are wiped on completion or failure. No persistent file handle,
wire-format change, new capability or data migration is required. Adapters
without writeChunks retain the single-chunk path (including current AoNs).

Preserved contract
- Every requested index, Merkle proof and AEAD check still runs per chunk.
- Account/job liveness checks remain; no checkpoint covers a partial write.
- Fixed-offset replay is idempotent after an interrupted or partial batch.
- Pending plaintext is discarded on corruption, lock, cancellation or error.
- Complete file byte-count/checksum verification precedes signed receipt.
- Group recipients retain independent file verification and receipts.
- Existing partial downloads and descriptors retain their format.
This is implementation validation, not a new cryptographic security proof.

Verification and preservation
All eight received files matched exact byte counts and SHA-256; all sender
delivery receipts confirmed. All receiver route evidence was complete,
payload-scoped peer delivery with no observed relay IDs. Available phone
stage counters showed no errors. Account and every pre-existing message key
were checked before/after: Dev 365 -> 373, FirstNeuron 141 -> 149. All added
messages are synthetic test transfers and remain in history.

Remaining focus
Integrity verification/decryption still costs roughly 0.8–0.9 seconds/MiB
in the isolated Dev profile. Request/response pacing and AoN-side serving
and receiving remain candidates, but these overlapping timings do not isolate
their wall-time cost. Any AoN deployment needs a fresh user approval. Native
or crypto changes require separate compatibility/integrity validation; do not
trade verification or durable receipt semantics for a faster benchmark.
