CONFIRMED GAPS / PRIORITY

P1 — Play Store update flow is disconnected.
Evidence: modules/axonic-app-update/src/index.ts exposes check/start/complete/install-state APIs and the Kotlin module remains. No active src caller invokes these APIs. The former AppUpdateGate, versionCheckService and versionPolicy are deleted; index.ts starts LocalAccountApp without an update observer.
Impact: Axonic itself no longer checks/prompts/resumes the original in-app update flow. This says nothing about Google Play's independently configured automatic updates.
Next: reconnect a Play-only update service to foreground lifecycle, with deduplication, cancellation cooldown, downloaded-update state, and safe restart coordination with active calls/transfers. Keep missing-store/offline/error states nonblocking; do not reintroduce the Django version endpoint. Expose state/actions for the UI chat. Verify actual store eligibility later on a Play-installed build; Dev/sideloaded tests cannot establish that.

P1 — Crash-reporting initialization is disconnected.
Evidence: crashReporting.ts defines configureCrashReporting, but no caller exists in the active entry graph; app.config.js retains Sentry build integration with useNativeInit:false. Privacy filters and tests remain as intentional support roots.
Impact: build-time symbol configuration is not evidence of active runtime crash reporting.
Next: restore deliberate privacy-filtered startup integration and test lifecycle/error handling. Preserve exclusion of messages, identity secrets, screenshots and breadcrumbs. Review current reporting intent before enabling additional telemetry; do not send a test event automatically.

P1 — Group mute is missing at the model/service level.
Evidence: original GroupInfoScreen used mutedRooms/toggleRoomMuted. RootGroupTypes contains accepted/blocked but no muted preference. rootMessageWake checks contact muting by sender; it has no group-scoped mute decision.
Impact: blocking a group is not equivalent to muting it; muting a contact also differs from muting one group.
Next: add backward-compatible local group notification preferences, enforce them in foreground and background delivery, and expose a module API. UI chat adds the control using that API.

P1 — Group read receipts are local-only.
Evidence: rootChatLedger.markGroupRead changes incoming messages' read flags and saves locally; it enqueues no receipt. RootGroupAction supports edit/delete/reaction, not read. rootGroups aggregates outgoing read flags, but the group read operation does not send the state back to authors.
Impact: marking a group read clears the local unread state; it does not establish remote blue-check/per-member read status. Delivery receipts are implemented separately and must not be presented as read receipts.
Next: implement authenticated per-recipient read acknowledgments, persistent retry/deduplication and aggregation tests before wiring the original group message-info/read presentation.

P2 — Group photo parity is missing beyond styling.
Evidence: original group info called uploadGroupAvatar; current membership consists of id/admin/name/revision/members and no image reference. RootGroupInfo renders a placeholder Avatar without a group URI.
Next: define local/shared group-photo behavior, ownership, encrypted attachment delivery, persistence and cleanup before UI wires a picker. Do not restore the old Django upload endpoint.

P2 — Incoming identity links have no active handler.
Evidence: app.json declares scheme axonic; current NavigationContainer has no linking configuration, and src has no getInitialURL or URL-event listener. QR scanning and pasted identity codes are separate active paths.
Next: define new identity-link parsing and cold/warm-start routing, including locked-account deferral and malformed-link rejection. Legacy numeric room/tag links should not be silently trusted or mapped to new identities.

P2 — Account lifecycle parity needs an explicit replacement.
Evidence: current account controls include local username/password, biometrics, lock and public recovery-record export; the previous server Delete Account / Logout All flows are absent.
Next: distinguish local data removal from cryptographic device revocation and identity retirement. A server-wide delete/logout cannot simply be retained under the new model. No destructive implementation or test is authorized by this audit alone.

P2 — Production instructions are stale.
docs/production-neuron-release.md describes manual FirstNeuron registration, legacy flags and Django calls/media. It is historical evidence, not current release instructions. Current index.ts has one local-account entry; eas.json production is an AAB with remote auto-increment, and submission still defaults to internal track. app.json/package version is 1.1.6; the next remote version code and intended store track still need checking before build/submission. No remote configuration was changed.
