Changes (local/Dev only; live AoNs not deployed)
1. Successful attachment custody publication is memoized in a bounded 128-entry,
   generation/owner/digest-scoped set. Receipt polling still runs, but does not
   repeatedly reread chat history to publish the identical stored marker.
   Failed callbacks are not cached. Invalidation/restart rechecks durable state.
   Signed final receipts remain mandatory for delivered/completed status.
2. Profile recovery first checks the revision-scoped history view. Known profile
   capabilities skip redundant ledger mutation; unknown capabilities persist and
   then refresh the view. Permission checks before sharing remain intact.
3. Relay test harness now observes file custody separately from independent
   descriptor custody. The latter is checked after file custody: its delta is
   time to observe/check it, not necessarily time the server first stored it.

root cause from the old aggregate timing. Stored-file status polls were waiting
