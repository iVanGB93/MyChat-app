GROUP CALLS - DEVELOPMENT IMPLEMENTATION AND ACCEPTANCE
2026-10-31. Enabled only in Dev; not a production readiness declaration.

Architecture
- groupCallRoom.ts binds immutable room ID, group, membership revision and sorted
  participants to signed call controls. Each pair has a deterministic leg ID and
  offerer. Only a creator invitation can open a ringing room. Other pair invites
  wait for that invitation and the local user's explicit acceptance.
- groupCallCoordinator.ts composes the existing durable private-call coordinator
  per pair. Membership and blocked contacts are checked again before admission.
  Departure ends the local participant's legs; it does not end other pairs.
- groupCallCapture.ts and RootGroupCallMedia.tsx own one microphone/camera capture
  per room. Per-peer hooks own negotiation and senders, not capture lifetime.
- Existing authenticated data WebRTC connections are borrowed and pinned against
  normal pool eviction. Hangup releases media use, preserving the data connection.
  Missing direct peers retain the dedicated TURN fallback.
- Call readiness uses subscriptions plus an expiry deadline. No new idle polling.
  An initial media setup deadline prevents indefinite Connecting tiles.
- Group legs remain in durable journals but are excluded from private call bubbles.
- Portable protocol/coordinator/connection changes are synchronized to the local
  AoN source and type-checked. No AoN source release was deployed in this task.

TURN finding and authorized server changes
FirstNeuron /etc/turnserver.conf previously had user-quota=4, total-quota=30,
max-bps=500000 and bps-capacity=2500000. Increasing allocation counts alone did
not fix the failure: exactly five relay allocations were available. With explicit
user approval, user-quota=64, total-quota=1024 and bps-capacity=25000000 are now
applied; max-bps remains 500000. coturn was restarted and is active. The subsequent
three-way forced relay test passed. This does not demonstrate capacity for 1,024
simultaneous allocations: bandwidth and the existing 49160-49200 port range are
separate bounds. Larger rooms/concurrency require measured capacity planning.
Reference: https://github.com/coturn/coturn/blob/master/docker/coturn/turnserver.conf

  signed subset. Nonselected members receive no invitation and cannot join it.
- Group history uses filtered compact journal projections and deduplicates mesh
  legs by room ID. One local call entry appears in the group timeline, on the
  creator's side; private history excludes these legs. It does not claim delivery
  of history entries to nonparticipants or distinguish answered/missed outcomes.

Incoming preview and rejoin (Dev)
- Incoming group video uses the same foreground/permission-gated local camera preview as private video. Capture is stopped before room capture begins.
- Lower remote participant label is at the top of its tile.
- Latest group call history exposes Join for its signed original audience. Availability is verified on tap, not inferred from an old history entry; there is no continuously synchronized room-presence indicator yet.
- Optional signed rejoin nonce derives fresh pair IDs within the same immutable room. Active accepted peers admit the fresh legs; inactive or unrelated rooms reject without ringing. Event-driven call availability
- groupCallPresence tracks each invited participant's own active state over authenticated encrypted chat transport. These ephemeral packets are intercepted before message/history storage. No periodic heartbeat or room polling.
- Subscribe/query once on chat open, catch up on a new authenticated connection, publish on participant state transitions. Only failed events receive three bounded delivery retries. Unknown/disconnected peers cannot enable Join; policy changes remove unauthorized availability.
- Join is shown only for the latest matching-revision call with a currently connected participant reporting active. Closing the last pair publishes inactive and removes Join. This is observed network state, not a guarantee during an undetected partition; disconnect detection fails closed.
- Delayed control for retired legs cannot recreate them alongside replacement connections. Membership revisions now also wake call-policy checks.
- Live phone + two emulators: three leave/rejoin cycles passed (3.9, 5.9, 8.3 seconds); two active connections per device, unaffected emulator pair retained its native connection throughout. After final departures Join became unavailable in 2.6 seconds. All test calls ended.
