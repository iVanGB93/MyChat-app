Findings and priority
  1. services/identity is a mixed implementation bucket (152 files): identity,
     connections, custody, media, calls, notifications and mobile adapters. Folder
     name obscures ownership. The new guides map these responsibilities now;
     physical extraction should follow stable ports, one area at a time.
  2. Messaging facade mixes text/groups, calls, media and diagnostic exports.
     Network facade forwards composition operations. Useful UI protection already
     exists, but these facades are not independent portable packages. Avoid moving
     their index files into hosted code; extract small dependency-injected ports.
  3. Mobile neuronRuntime (330 lines) and hosted index (479 lines) join many domains.
     Some lines are dense, so line count understates responsibilities. Hosted entry
     also mixes server routes/dashboard/auth/wiring. Extract constructors/routes
     with lifecycle tests; do not spawn a new manager/runtime for every feature.
  4. Phone delivery.ts and hostedRootChat.ts schedule shared ledger/protocol work
     separately. This is an orchestration parity seam, not proof of duplicate
     wire protocols or of a bug. Compare approval, concurrency, wake and retries
     before deciding whether a shared scheduler is actually appropriate.
  5. Connection selection, transfer route choice, own pending work and relay custody
     span multiple layers. Keep separate ports and evidence: reachable != saved !=
     delivered != read. The proposed store manager must not own all four.
  6. Largest mobile hotspots include useWebRTCCore (731 lines), persistentAxon
     (696), RootAccountNavigator (602), attachmentTransfer (457). Prioritize by
     responsibility/test seam, not by line count alone. No performance improvement
     is claimed from directory/documentation changes.
  7. Boundary checker uses a curated screen list and specific factory/store checks.
     It does not enforce a universal ten-module dependency graph. Cycle detection
     and reachability supplement it. Broaden enforcement only after importing
     actual dependencies into a reviewed allowlist; avoid broad exceptions.
  8. Durable state, runtime state and presentation projections must stay distinct.
     A global UI store is not the answer for authorization, sockets or file custody.
  9. Documentation drift: START-HERE still described a pre-single-copy/state1.1.27
     artifact; app-modules described five boundaries and historic FirstNeuron
     integration status; hosted SHARED-SOURCE included an old uncommitted baseline.
     Current entry pointers now lead here; dated historical evidence is preserved.
 10. Muse's live hook is external. MCP/OpenClaw source is inspectable here, but local
     packages cannot certify all three live integrations or their current settings.
