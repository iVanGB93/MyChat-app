AXONIC MODULE AUDIT — NOVEMBER 1, 2026

Scope and release boundary
Reviewed the ten architecture responsibility areas, exercised two Android Dev
emulators, checked all three deployed AoNs, and ran mobile, hosted and MCP suites.
This is a bounded audit, not proof of every device, network or failure condition.
No identities, messages, queues or approvals were reset. Labelled emulator test
messages, groups and attachments were added and retained. Official phone apps
were not used. No production build, publication or installation was performed.
Unrelated working-tree changes were preserved.

Implemented findings
1. Audio interruption: RootAudioPlayer now observes account, call and recorder
   state instead of polling permission every 250ms during playback. Recorder
   activity is published from its existing controller; cleanup remains isolated
   from subscriber errors. RootVoiceComposer cancels from call events, including
   while starting. The elapsed-time display updates once a second rather than
   four times. Recording presence renewal remains necessary for the remote TTL.
2. Transfer presentation: a selection change while progress is being read now
   triggers an immediate coalesced reread. Previously it unnecessarily waited
   one second. Real read failures retain backoff; background UI does not retry.
3. Storage error recovery: a chat write arriving during a failed read no longer
   bypasses the retry backoff and creates an immediate failing read loop. New
   successful-write events can still wake recovery promptly.
4. Hosted call courier: replaced the unconditional one-second cache sweep with
   the existing shared deadline scheduler. The shared relay exposes the earliest
   expiry and notifies when that deadline changes; an empty cache has no expiry
   timer. Expiration, validation and shutdown behavior are retained.
5. Chat header animation: the infinite syncing decoration used interaction
   animations, which can defer virtualized-list work. All wave and pause stages
   now run natively without interaction handles. The existing component tests
   exercise changing title length, teardown and non-interacting configuration.
   This fixes a concrete scheduling risk; it does not establish the cause of all
   historical scroll-lock reports.

Remaining priorities / honest limits
1. Capture a controlled physical-phone profile for scrolling and cold chat entry.
   The emulator's mixed frame sample still has spikes; do not certify smooth
   production performance from it. Keep the new header fix in that next check.
2. Repeat real screen-off/killed-process notification recovery on both phones,
   including 5/10 MB files and network changes. A backgrounded emulator is not
   equivalent to Android OEM battery restrictions.
3. Profile authentication/discovery traffic separately before reducing transport
   maintenance. Do not remove expiry, exchange timeout, lease or authentication
   work simply to make timer counts smaller.
4. Storage overview intentionally scans selected attachment metadata/files; it
   is not the chat-list startup path. Large-account profiling can establish
   whether paging/batching here is worthwhile without introducing another cache.
5. Long-running AI reconnect/renewal tests and four-party hardware call tests are
   outside this pass. The server integration tests and health checks cover their
   server contracts, not their external runtimes or microphones/cameras.

Timers retained intentionally
Protocol expiry, authentication renewal, reconnect backoff, bounded exchange
timeouts, remote typing/recording TTL renewal, elapsed-time displays and missing
native-event fallbacks. These have time-based correctness requirements. Most
idle message/call/attachment tasks already sleep until an event or real deadline.
