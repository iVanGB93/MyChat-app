Contract: one composed runtime shared by foreground/background consumers, bounded
leases and work, invalidation on lock/account switch, deterministic cleanup.
Wake hints request recovery; they do not prove delivery. Distinct hints can share
a pump while retaining separate completion observations. Deadlines bound work.
Process CPU covers all threads and overlapping intervals must not be added.

State authority: services/ledger own domain state. Zustand stores project it for
UI through subscriptions/selectors, not a parallel authoritative database.
No native tracks, private keys, long-lived socket objects or approval overrides
in UI stores. Cache epochs and stale-read handling matter more than store branding.

Shared attachment scheduling (October 25)
  Phone and AoN now use canonical createWorkPump: single flight, coalesced events,
  immediate yielding progress, explicit idle deadlines, five-second error retry.
  The hosted adapter injects Node unref timers; phone uses its own timer/lifecycle.
  Both use attachmentWorkDelay and createAttachmentReconcileGate. Empty queues
  have no timer; blocked or unusable routes wait for an event or expiry. Productive
  bursts do not repeatedly enqueue every unchanged descriptor. Recovery's 30-second
  reconciliation bound is checked on work, not driven by a new polling timer.
  Phone topology/capability changes now explicitly wake attachments, in addition
  to connection, chat-write, selection, owner and resume events. Hosted network
  onChanged and committed chat writes already flow through rootChat.changed.
  Global UI state subscribes to these authorities; it is not used as authorization
  or transfer readiness. This avoids requiring an active screen/store subscriber.

Retained platform behavior
  Phone preparation is a separate single flight, with a 15-second pending-selection
  retry. Mobile worker bursts allow 32 steps/50ms; hosted uses 8 steps/50ms.
  OS background leases, account locking, Gallery export and native sockets stay
  mobile-specific. Node upload endpoints, filesystem/SQLite and unref stay hosted.
  Expiry, protocol backoff, missing remote receipts and storage errors still need
  deadlines. A UI state change cannot replace those timers. Other messaging/call
  tasks keep eventDeadlineTask; do not merge different domain completion rules.
