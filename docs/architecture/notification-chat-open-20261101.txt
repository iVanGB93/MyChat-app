Finding: indexed canonical writes defer presentation work while backgrounded.
The previous dirty marker did not retain the affected conversation keys, so the
next chat/index read rebuilt the projection from the complete canonical history.
This adds avoidable history work when opening a notification on a large account.

Change: sparse commits durably union dirty conversation keys before canonical
commit. On foreground demand, the existing indexed readRooms API and existing
partial projection publisher repair only those rooms, using current canonical
metadata/actions. No new timer, queue or parallel cache. Multiple background
updates and process restarts retain the union. Metadata-only changes use an empty
room set with fresh metadata. Full writes, unknown/invalid dirty scopes, missing
indexes and damaged pages retain full recovery. Read failures remain failures;
they never publish an empty replacement or erase the durable recovery marker.
