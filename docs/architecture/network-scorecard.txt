NETWORK SCORECARD — 2026-10-31

Shared core: src/services/identity/networkScorecard.ts. Used by phones and the hosted network. No reward/combined score. Contribution and connection health are separate objects.

Contribution comes from existing durable custody transitions, after transaction success: private message storage, accepted group job, unique encrypted media blocks/bytes, media grants, and first verified recipient receipts. Duplicate deposits/blocks/receipts and rollback do not add counts. Shared group content is counted on actual first block insertion, not once per recipient grant. Ciphertext bytes are decoded payload bytes, not wire bytes or plaintext size. Receipt evidence does not establish that this relay supplied all content; the recipient may use another route.

No polling, new scheduler, database table, message scan, or identifier history is added. Existing change notifications refresh the phone global network state and hosted dashboard. Diagnostics include the same scorecard under network.evidence.scorecard; hosted status/monitoring exposes scorecard. Existing custody tombstones provide idempotency, not a separate reward ledger.

Scope: each service instance has startedAt; counters are local, volatile observations. A restart/account switch creates a new window. Uninstantiated services are null/unavailable, not zero. No historical backfill or claimed lifetime total. Pending storage residence, independently verified availability and actual forwarded throughput remain explicitly unavailable. These cannot responsibly be derived from a receipt, an ACK or process age. This is not tamper-proof accounting or a basis for payments.

Health reports current network state, connected-peer count and runtime error separately. A low-traffic neuron is not classified unhealthy. No inference of CPU, battery, storage integrity or delivery success.
