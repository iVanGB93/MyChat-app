Current API: messaging.sendText/act/markRead and group commands persist intent
before delivery. conversations() exposes reads/preferences instead of raw inbound
admission. Factories in commands.ts/delivery.ts accept injected dependencies;
the public index.ts is mobile composition, not a portable import for hosted code.
Hosted root-chat orchestration currently has its own scheduler around the shared
ledger/protocol. Shared protocol does not mean identical phone/AoN orchestration.

State authority: ledger and durable action/outbox records. Preserve logical group
message IDs vs per-recipient wire IDs. Retries cannot invent new logical messages.
Receipt acceptance, relay storage and user reading are different facts. Sending a
reply or exporting history is not itself a read acknowledgment. Group deletes must
resolve original author and logical target; never use local chat deletion instead.

Courier receipt evidence may survive overlapping wake resumes; fresh relay drain
is still needed, and account invalidation clears it. The local Oct25 fix is not
proof that a particular deployed phone now has that behavior.
