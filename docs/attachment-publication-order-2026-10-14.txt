Attachment publication and serving readiness — 2026-10-14

Finding and fix
prepareSelection previously published the chat descriptor before persisting the
outgoing attachment job. A connected recipient could request bytes during this
gap and receive unavailable. Now all outgoing jobs are saved before single/group
descriptor publication. Storage failure does not advertise an unservable file.
Unpublished jobs remain subject to the existing chat policy and cannot be served.

The serving entry point also refreshes its cached chat policy when ownChatRevision
changes. Requests no longer depend on the next 200 ms pump to observe a new
descriptor or block decision. Account and runtime epoch are checked after await.
Protocol, encryption, final checksum and signed receipts are unchanged.

Tests
Scheduling tests verify publication order for single and group attachments,
storage failure before publication, immediate permission refresh, blocking and
locking. Full npm run check: 1119 passed, 3 skipped, no failures; typecheck,
cycles, module boundaries and consolidation passed. git diff --check passed.
