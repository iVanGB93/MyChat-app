Transport contention follow-up — October 25, 2026

Confirmed code-level problem
persistentAxon.custodyRequest returned null both for unavailable/unauthorized
sessions and for local queue saturation or exhaustion of its bounded2s wait.
The private courier treated the latter like a failed relay and excluded that
relay/recipient pair for120 seconds. This is a deterministic false cooldown,
not proof that it caused the historical58s sample.

Fix (shared source; local/Dev only)
- Valid sessions with a full local custody queue, pending push work or exhausted
  local contention wait return status=retry,retryAfterMs=1000.
- Invalid sessions and oversized requests still return null. Queue bounds and
  push/call priority unchanged. No request is marked held/delivered by a retry.
- Courier honors retry hints with a bounded1–60s delay (invalid hint5s), still
  tries alternative relays, and preserves120s cooldown for actual failures.
- Existing receipt/drain safety remains unchanged.
