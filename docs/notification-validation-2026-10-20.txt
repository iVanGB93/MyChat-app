Notification and call validation — October 20, 2026

Implementation
- Signed FCM routing hints no longer display speculative message notifications.
  Recovery still runs; notification previews require durable decrypted admission.
- A matching legacy generic notification can be removed during wake handling;
  newer/decrypted conversation notifications are preserved.
- Small messages can travel as encrypted inline custody envelopes inside the
  3,500-byte application budget. Larger packets and some fallback paths remain
  retrieval hints. This does not mean every FCM wake carries a complete message.
- Incoming calls now request full-screen presentation and Answer/Decline actions.
  Android 12+ uses native Notification.CallStyle while retaining Notifee IDs,
  pending intents and cancellation. Android settings still govern presentation.
- Call actions are matched to the current verified account/call, expire after
  60 seconds, and execute through the foreground call UI and permission checks.

Limits / follow-up
- No production build or AoN deployment performed.
- Production app retains old behavior until a future approved build.
- Full-screen display is subject to OS permissions/settings; shade action layout
  was not separately visually verified because the phone opened full screen.
- Warm background tests are not deep Doze or killed-process FCM validation.
- Background delays remain measurable; do not interpret removal of generic
  alerts as proof that all wake/recovery performance issues are resolved.
- Existing local AoN scheduling changes have not been deployed by this work.
