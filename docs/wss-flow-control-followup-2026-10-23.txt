Relay-stream answer/design, NOT implemented in this change:
Reuse the authenticated connection and bounded transport machinery, carrying the
original encrypted 3 MB block unchanged. Relays get no destination decryption key.
Use a separate custody adapter: reserve quota, stream to attempt-owned temporary
storage, verify the existing signed block proof/length/index, commit durably, then
acknowledge storage idempotently. That is not a recipient delivery/read receipt.
The current own-file manager cannot be directly used for custody because its
authorization, plaintext checksum and completion semantics differ. A binary wire
path could remove base64 expansion; it needs native/mobile and server changes.
