# Axonic audit — September 9, 2026

## Scope and evidence rules

Review and regression testing of the mobile app and backend. Passing unit tests
is not proof of end-to-end correctness. Development emulators cannot certify
physical-device audio quality, OEM background restrictions, or Play updates.
Existing user changes and emulator data are preserved. No production deployment,
commit, reinstall, or production build is part of this audit.

## Changes in this audit

- Confirmation dialogs now use one ordered queue and ref-based unique IDs.
  Removes a delayed-close race that could replace or skip another dialog.
- Guard against double-tapping a confirmation action during its closing animation.
- WebRTC signals now include a call scope inside relay-preserved data. Updated
  clients reject explicit mismatched call scopes and strip metadata before passing
  to WebRTC. Legacy unscoped clients remain accepted during rollout, so they do
  not gain the full stale-signal protection until updated.
- Removed compiler-confirmed unused imports and dead dialog code. Retained API
  parameter positions where changing signatures would cause unnecessary churn.
- Strict unused-local/parameter TypeScript validation passes after these changes.

## Additional fixes

- Call timer/connected state now follow WebRTC connectivity, not acceptance alone.
  Connecting attempts time out; local media stops before awaiting server hang-up.
- Await ICE configuration before creating the peer connection, avoiding a race
  that could ignore TURN/relay configuration when media acquisition was faster.
- Permission acceptance rechecks cancellation and prevents concurrent accept taps.
- Single-flight camera prewarming releases late streams after cancellation and
  hands an in-flight preview to the active call without opening a second camera.
- Dark label backgrounds improve contrast over bright video without tinting the
  entire video. This last style change still needs post-change visual review.
- Permanent HTTP 404/410 media failures are persisted per media pointer, excluded
  from automatic hydration/recovery, and do not generate false delivery receipts.
  A fresh re-upload pointer is saved and can recover. Tests include app restart.
- Backend blocks new calls across blocked relationships. Join/end take row locks
  to serialize conflicting changes. SQLite tests cover terminal state semantics;
  PostgreSQL concurrent-request verification is still needed after deployment.
- Metro now excludes generated Android build/cache trees while retaining native
  module source directories and existing exclusions. Expo restarted and both apps
  bundled. This is a mitigation for Windows EMFILE, not yet a proven root-cause fix;
  a longer development-session stability test remains necessary.

## Open findings / remaining coverage

- Backend deployment confirmed after the user reported deployment; live call
  concurrency verification remains outstanding.
- Live ICE logs reported only two servers; direct P2P works here, but a TURN relay
  path has not been demonstrated. Inspect production TURN availability and test
  different restricted networks before claiming reliable calls everywhere.
- Camera-cancellation regression is automated; repeat on a physical device.
- Offline resend, reconnect, multi-file transfer, notification actions, edit/delete,
  read/delivered transitions, local pruning/migrations, and account switching still
  require scenario-specific live coverage beyond the existing automated tests.
- Group calling is not exposed in ChatRoom: call buttons are direct-chat only.
  Implementing multi-party calling is a separate feature, not a verified capability.
- Physical-device and Play-installed update tests remain release requirements.
